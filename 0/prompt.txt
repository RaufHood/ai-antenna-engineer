This is a hackathon project: an autonomous agent (Devin) proposes antenna

## Solver policy — decided, do not change it

*Use PyNEC. It is the fast path and it is already the default.* No action
needed: it installs with plain pip as a backend dependency.

Measured on the working machine, one solve at 21 frequency points:

| band            | mesh   | segments | ms/solve |
|-----------------|--------|---------:|---------:|
| LTE low 0.9 GHz | 3x6    |       27 |      4.6 |
| GPS L1 1.6 GHz  | 5x9    |       76 |       21 |
| *Wi-Fi 2.4*   | 7x13   |      162 |   *83* |
| n78 3.8 GHz     | 10x20  |      370 |      400 |
| Wi-Fi 5.8 GHz   | 15x29  |      826 |     2007 |

The whole agent loop — 2 iterations, 19 solves — runs in *0.79 s* with the
mock agent. The solver is not the bottleneck; the agent's reasoning is (~98%
of wall time on a real Devin run).

Two knobs if you ever need it faster: the mesh pitch is lambda/10 at the top
of the band, so *lower frequency = far fewer segments* (2.4 GHz is 24x
cheaper than 5.8 GHz, and the cost goes as segments^3), and ⁠ n_freq ⁠ scales
linearly. Do not reach for numba — PyNEC is a compiled C++/Fortran extension,
numba only speeds up Python and would do nothing here.

## Traps — please read, these cost us real time

*Do NOT install or build openEMS.* It is an optional alternative solver that
is ~1000x slower than the default (minutes vs 83 ms per solve) and takes about
an hour to build from source. ⁠ rf/README.md ⁠ documents three environments —
you need none of them for the agent loop. If something reports openEMS
missing, that is expected and handled; the backend falls back cleanly.

*Do NOT create ⁠ rf/.venv ⁠ or a bpy environment.* Only needed to regenerate
device geometry from a ⁠ .blend ⁠, and that output is already committed as
⁠ rf/blend_loader/out/device.json ⁠.

*Anything gitignored does not come with a clone.* If something behaves
differently from a teammate's machine, check ⁠ .gitignore ⁠ first — that is
almost always where the difference is.
